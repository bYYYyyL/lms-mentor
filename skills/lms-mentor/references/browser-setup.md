# 浏览器控制与连接

先检查 agent 自带的浏览器、桌面操作工具及其使用说明。可用且能操作用户指定的已登录会话时优先使用。工具缺失时，检查当前环境是否允许安装依赖、启动可见浏览器和交互；有对应官方插件时可按该平台的说明配置。

## 本地 Playwright 备选方案

在支持本地 Python、图形界面和浏览器控制的环境中，可以使用本技能的 `scripts/browser_session.py`。这是独立的可见浏览器会话，不会连接或复制用户现有的浏览器配置、Cookie 或登录状态。如果用户要求必须使用某个现有会话，则不得擅自切换；说明限制，等待用户选择是否使用新会话。

1. 在用户授权且环境允许的工作目录创建独立 Python 虚拟环境，安装 `playwright`。使用系统已有 Chrome 或 Edge 时选择相应 channel；如需 Playwright Chromium，则按 Playwright 安装说明安装浏览器。依赖安装或权限被拒时报告，不绕过限制。
2. 以持久交互进程运行 `python <skill目录>/scripts/browser_session.py --profile <工作目录中的独立配置目录> --channel msedge --url <LMS地址>`。Windows、macOS 或 Linux 上仅当指定浏览器实际已安装时使用 `msedge` 或 `chrome`；否则可使用已安装的 `chromium`。不要指向用户现有浏览器配置目录。无图形界面或无法显示窗口时停止并说明。
3. 让用户自行在新开的可见窗口登录、完成验证，并明确告知已完成；不要要求密码或验证码。保持进程和浏览器打开。配置目录可能包含登录状态，应保留在用户控制的私有工作目录，不上传或分享。
4. 进程的标准输入每行接受一个 JSON 命令，标准输出每行返回一个 JSON 结果。例如：`{"op":"status"}`、`{"op":"text"}`、`{"op":"elements"}`（列出可见控件和选择器）、`{"op":"click","selector":"button"}`、`{"op":"fill","selector":"textarea","value":"..."}`、`{"op":"screenshot","path":"<工作目录>/page.png"}` 和 `{"op":"close"}`。`goto` 接受 `url`。根据当前页面重新定位选择器并核对操作结果；不要对密码或验证码输入使用 fill。`--headless` 仅供本地无登录页面测试，不用于要求用户手动登录的场景。
5. 连接失败或无响应时立即报告并停止自动重试。用户处理并要求继续后再尝试。技能无法保证所有系统、agent、设备或 LMS 允许该方法；无法使用时报告实际限制。
